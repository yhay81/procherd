# ProcHerd adopters

This file records verified, opt-in adoption rather than treating stars,
downloads, or repository clones as proof of use.

No external adopters have been recorded yet.

The shortest reporting path is the public
[adoption report form](https://github.com/yhay81/procherd/issues/new?template=adoption_report.yml).
Use a pull request instead when the evidence should be committed directly to
this file.

Reports credited toward the v1.0 gate identify the reporter's relationship to
the project plus first and latest use dates. Repeat-use credit requires two
independent observations at least 30 days apart; maintainer self-evaluation,
downloads, clones, and stars do not count.

If ProcHerd owns processes in a reproducible workflow, open a pull request
with:

- a public project or organization name;
- the workload type, such as a dev server, watcher, test service, or build;
- the lifecycle features used;
- supported operating systems;
- the lifecycle, recovery, or coordination decision ProcHerd improved;
- whether use repeated after at least 30 days;
- leaked processes, stale state, false readiness, or lease conflicts
  encountered;
- a link to public integration evidence when available;
- whether the entry may be referenced in release notes.

Private users may instead open a discussion without identifying details.
Aggregate adoption claims will not be added without permission.

Never submit credentials, private paths, environment values, proprietary logs,
or unreviewed state documents.
